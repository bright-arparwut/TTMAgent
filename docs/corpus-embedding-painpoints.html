ข้อเสนอ 3
เพิ่ม heuristic ใน load_jsonl (app/rag/ingest.py): chunk ที่เป็นหัวข้อ/ป้ายล้วน (สั้น, ขึ้นต้นด้วยเลขข้อ, ไม่มีประโยค) ให้รวมเข้ากับ chunk เนื้อหาถัดไปแทนการเป็นเวกเตอร์เดี่ยว — ทำได้ทันทีวันนี้โดยไม่ต้องแตะ OCR (แค่รัน ingest ใหม่)
ข้อเสนอ 4
ใน retrieve_passages (app/rag/vector_store.py): ดึง dense มา k=30 → ให้ cross-encoder ให้คะแนน (query, chunk) เป็นคู่ → เลือก top 5 — ไม่ต้อง ingest ใหม่เลย ใช้ได้กับ index ปัจจุบันทันที

ปัญหาที่ 5 · ทิ้งอาวุธที่มีอยู่แล้ว

ใช้ dense อย่างเดียว — ทั้งที่ BGE-M3 คำนวณ sparse ให้ฟรีอยู่แล้ว

ศัพท์เฉพาะทางหลายคำโผล่ใน corpus แค่ 1–2 chunk (ข้อมูลจริงด้านล่าง) — คำแบบนี้ sparse/BM25 “ล็อกเป้า” ได้ทันทีด้วยการจับคำตรงตัว ส่วน dense ต้องงมจากย่อหน้าที่ความหมายคล้ายกันเป็นสิบ ๆ ย่อหน้า BGE-M3 ผลิต sparse weights ออกมาใน forward pass เดียวกับ dense อยู่แล้ว แต่โค้ดปัจจุบันทิ้งมันไป

จำนวน chunk (จากทั้งหมด 1,862) ที่มีคำนี้อยู่จริง — ข้อมูลจริง

คะแนนจำลองเพื่อการอธิบาย (normalize เป็น 0–1)

ข้อเสนอ 5
เก็บ sparse weights ของ BGE-M3 ไว้ตอน ingest แล้วทำ hybrid retrieval (dense + sparse ถ่วงน้ำหนัก) ใน retrieve_passages (app/rag/vector_store.py) — ได้ผลแรงสุดกับศัพท์เฉพาะที่พบน้อยครั้ง และคู่คำที่ต่างกันพยางค์เดียวอย่าง “ลมปราณอิ๋ง” vs “ลมปราณเว่ย”

ปัญหาที่ 6 · สมมติฐานที่ไม่มีเทสคุ้มกัน

ไม่มีอะไรยืนยันว่าเวกเตอร์ถูก normalize — แล้ว Chroma ก็จัดอันดับด้วย L2

app/rag/embeddings.py สร้าง HuggingFaceEmbeddings โดยไม่ตั้ง encode_kwargs={"normalize_embeddings": True} และ app/rag/vector_store.py สร้าง Chroma โดยไม่ตั้ง collection_metadata={"hnsw:space": "cosine"} → ใช้ L2 (ค่า default) ถ้าเวกเตอร์ยาวไม่เท่ากับ 1 การจัดอันดับด้วย L2 จะไม่เท่ากับ cosine เพราะความยาวเวกเตอร์ปนเข้ามาในระยะ — เชื่อว่า bge-m3 normalize ให้อยู่แล้ว (มี Normalize module ในตัว) แต่ยังไม่มีเทสยืนยันสักบรรทัด

คำถาม q เทียบเอกสาร A (ทิศเกือบตรงกัน, เวกเตอร์สั้น) และ B (ทิศเฉียงออก 22°, เวกเตอร์ยาว)

เอกสารมุมห่างจาก qความยาวระยะ L2อันดับ
A — ทิศตรงคำถาม3°0.45
B — ทิศเฉียงออก22°1.15

# tests/rag/test_vector_store.py
def test_query_embedding_is_unit_length():
    vec = get_embeddings().embed_query("ลมปราณ")
    assert abs(sum(x * x for x in vec) ** 0.5 - 1.0) < 1e-3
ข้อเสนอ 6
เพิ่มเทสข้างบนใน tests/rag/test_vector_store.py — ต้นทุนแทบเป็นศูนย์ ถ้าเทสผ่าน = ยืนยันว่า L2 กับ cosine ให้อันดับเดียวกันจริง ถ้าไม่ผ่าน = จับบั๊กการจัดอันดับที่มองไม่เห็นด้วยตาได้ก่อนขึ้น production (แล้วค่อยตั้ง normalize_embeddings=True / hnsw:space=cosine ให้ชัดเจน)
