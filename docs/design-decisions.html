At Consultation close (next message after a > 6 h gap) the working buffer passes the Relevance Gate and, if clinically relevant, is summarized into a Health Record entry — deterministically, never by an LLM tool call.

Decision ledger

Domain

01 The domain is Thai Traditional Medicine, not modern healthcare The bot is a TTM self-care advisor: it produces Assessments (never clinical diagnoses) grounded in the TTM corpus, and recommends a doctor for anything clinically serious.
02 Tongue-only visual assessment, one pipeline Every image goes through the tongue detector. Tongue found → Tongue Assessment; not found → retake guidance. Rashes, wounds, and arbitrary health images are out of scope — the corpus doesn't ground them and they dilute the thesis.

Memory

03 Health Record is the only persistent memory Doctor's-notes-style entries with a conversation summary; raw transcripts are never stored long-term. Mirrors how a real doctor charts a visit. (ADR-0002)
04 Consultations close lazily on a 6-hour inactivity gap Raw turns wait in a working buffer; the next message after the gap triggers summarization. No cron, no scheduler — everything happens inside webhook handling, and users who vanish mid-chat are handled for free.
05 Relevance Gate at close Memes, greetings, and off-topic chat are discarded without creating an entry — the chart stays clean because the last 3 entries are auto-injected into every new Consultation.
06 Auto-inject + read-only tools; no LLM write tools Recent entries load automatically (continuity never depends on a tool call); search_health_records and get_health_record_by_date cover deep lookups. Record integrity never depends on the model remembering to call save().

Models

07 Two-model pipeline: config-selected Advisor + separate Vision Describer Neither slot has a fixed model. The Advisor Model reasons over the corpus and calls tools; the Vision Describer only describes the tongue, never assesses. Both switch via config — e.g. Typhoon vs. a frontier model as Advisor is an experiment, not a rewrite. (ADR-0001)
08 Structured Tongue Description schema, derived from the book The Describer fills fixed TTM observation fields plus a notes field and an image-quality flag. Describer models become interchangeable and the two stages are separately evaluable.
09 Advisor Model and detector both reachable via hosted API Whichever model config selects for the Advisor slot (e.g. Typhoon) runs via its hosted API; Roboflow detector likewise hosted. Zero GPU ops, free tiers, reproducible enough for a thesis. Detector keeps a confidence threshold + crop padding as tunable constants.

Knowledge

10 RAG = Chroma (embedded) + BGE-M3 (local), plain top-k One book is a small corpus: chunk by the book's own sections, retrieve k≈4–6 per advisor turn. No re-ranker, no hybrid search. Plain MongoDB in Docker has no vector search — MongoDB stays for records only.

Delivery & ops

11 Webhook returns 200 immediately; pipeline runs in a background task Loading animation while thinking, reply token with push fallback, and per-user serialization so parallel turns can't race the buffer.
12 Deterministic spine in plain Python; LangGraph only for the advisor loop Detect → describe → retrieve is fixed code; only the Health-Record tool loop is agentic. Model slots are LangChain config, so swaps are .env edits.
13 Local dev behind a Cloudflare named tunnel; cloud VPS optional later FastAPI + MongoDB (Docker) + Chroma folder all local; the same compose stack moves to a small VPS if the evaluation needs always-on availability.

Safety

14 Three system-prompt-level safety rules One-time disclaimer on follow; red-flag escalation (emergency symptoms → drop TTM framing, direct to 1669); scope refusals (no dosing, no disease-cure claims, no pregnancy/infant herbal advice). No separate classifier model.

Ubiquitous language

Thai Traditional Medicine not "Thai healthcare"

The domain — แพทย์แผนไทย, incl. tongue inspection and element-based wellness.

TTM Self-Care Advisor not "doctor bot"

What the bot is. Never claims modern medical diagnosis.

Assessment not "diagnosis"

The bot's TTM-grounded interpretation of a user's condition.

Tongue Assessment not "tongue diagnosis"

Assessment from a detected-and-cropped tongue photo — the only visual kind.

Advisor Model not "the LLM" / "the Typhoon model"

Text LLM conducting the Consultation. Config-selected slot, no fixed default — e.g. Typhoon, GPT, Claude.

Vision Describer not "image model"

Multimodal model that describes tongue photos. Describes; never assesses.

Tongue Description not "caption"

Structured observation (schema from the book) + notes + quality flag.

Consultation not "session"

One bounded episode, like a doctor visit. Closed by the inactivity gap.

Health Record not "chat log"

Per-user structured entries + conversation summaries. The only long-term memory.

Relevance Gate not "spam filter"

Close-time check: only clinically relevant Consultations become entries.

Evaluation plan

Primary
Tongue Description accuracy

Labeled tongue-photo set vs. schema output; same photos through Gemini / GPT / Claude as the Describer — the model-comparison table.

Primary
Memory ablation

Returning-user scenarios with Health Record injection on vs. off. The thesis's most novel claim.

Primary
Safety escalation rate

Red-flag message test set (e.g. chest pain, breathing difficulty) → measured escalation-to-1669 rate.

Secondary
TTM correctness

Groundedness / expert rating of Assessments against the corpus — included, but not the headline.

Architecture decision records

ADR-0001
Two-model pipeline

Config-selected Advisor + separate structured-output Vision Describer, instead of one frontier multimodal model. No model is architecturally fixed; tool-calling risk travels with whichever model is configured, mitigated by a config-level escape hatch.

ADR-0002
Health-Record-only memory

Lazy gap-close summarization with a Relevance Gate; no LLM write tools. Changing this invalidates the memory-ablation experiment.
